# ClosedPort 更新流程

本文只讲一件事：如何把新版本做成安装包、放到更新服务器、让已安装的 ClosedPort 自动检查并静默安装。

请严格按顺序做。漏改版本号、只上传安装包不改清单、或清单版本不高于用户当前版本，用户都不会看到更新。

---

## 1. 整体流程（先看这一张图）

```
编辑 update.txt（版本号 + 更新日志）
    ↓
运行 scripts\update.ps1（改版本、打包、上传）
    ↓
用户打开 ClosedPort
    ↓
程序请求 http://111.230.247.111/closedport/latest.json
    ↓
清单里的 version > 本地 version ？
    ├─ 否：不提示
    └─ 是：右下角提示，设置里可点「立即更新」
            ↓
        下载 latest.json 里的 url 安装包
            ↓
        校验 sha256（清单里有值才校验）
            ↓
        用 /S 静默安装，然后退出当前程序
```

客户端**只会访问 HTTP**，不会用 SSH，也不会带服务器密码。

## 3. 版本号规则

程序用 `src-tauri/Cargo.toml` 里的 `version` 判断自己是不是旧版。

比较规则：把 `x.y.z` 拆成三段数字，**清单 version 必须大于本地 version** 才会提示更新。

例如：

- 本地 `0.1.0`，清单 `0.1.0` → 不更新
- 本地 `0.1.0`，清单 `0.1.1` → 提示更新
- 本地 `0.1.1`，清单 `0.1.0` → 不更新

发版时只在 `update.txt` 末尾追加一行 `版本号 更新日志`。脚本读取最后一行，并把版本号同步到：

1. `src-tauri/Cargo.toml`
2. `src-tauri/tauri.conf.json`
3. `package.json`

## 4. 开发机发布前准备（只需做一次）

### 4.1 确认本机有这些工具

- Node.js、Rust、Tauri CLI（能执行 `npm run tauri build`）
- Python 3
- Python 包：`paramiko`（没有就执行 `pip install paramiko`）

### 4.2 确认发布密码文件存在

打开 `scripts/.update-server.env`，内容必须是：

```env
UPDATE_HOST=111.230.247.111
UPDATE_USER=root
UPDATE_PASS=<服务器登录密码>
UPDATE_DIR=/usr/share/nginx/html/closedport
```

没有这个文件时，可复制 `scripts/.update-server.env.example` 再填写 `UPDATE_PASS`。

不要把这个文件提交到 git。

## 5. 发一个新版本（只改 update.txt，然后跑脚本）

下面用「从 0.1.0 升到 0.1.1」举例。

### 第 1 步：编辑 `update.txt`

打开项目根目录的 `update.txt`，**在文件末尾追加一行**（不要改历史行）：

```text
0.1.0 初始版本
0.1.1 这里写给用户看的更新说明
```

每行格式：`版本号 更新日志`。脚本只读取**最后一行**作为本次发版。保存后不要手改 `Cargo.toml` / `tauri.conf.json`，脚本会同步。

### 第 2 步：运行更新脚本

```powershell
cd D:\wwwroot\tauri\closedport
.\scripts\update.ps1
```

也可以：

```powershell
npm run update
```

脚本会按顺序做完这些事：

1. 读取 `update.txt` 最后一行的版本号和更新日志
2. 把版本号写入 `Cargo.toml`、`tauri.conf.json`、`package.json`
3. 执行 `npm run tauri build` 打 NSIS 安装包
4. 计算 SHA256，生成 `latest.json`
5. 用 SSH/SFTP 上传安装包并覆盖服务器清单

成功时终端会打印：

```text
清单地址：http://111.230.247.111/closedport/latest.json
```

只要改版本、不重新打包时：

```powershell
.\scripts\update.ps1 -SkipBuild
```

只要打包、先不上传时：

```powershell
.\scripts\update.ps1 -SkipPublish
```

### 第 3 步：核对服务器清单

浏览器打开：

http://111.230.247.111/closedport/latest.json

确认这 4 项：

| 字段 | 必须满足 |
|---|---|
| `version` | 等于 `update.txt` 里的版本，例如 `0.1.1` |
| `notes` | 等于 `update.txt` 最后一行的更新日志 |
| `url` | 能直接下载到刚才那个 exe |
| `sha256` | 不是空字符串 |
| `silentArgs` | `/S` |

再单独打开 `url` 里的地址，浏览器应开始下载 exe，而不是打开一个网页。

### 第 4 步：用旧版本客户端验证

1. 打开一台仍是旧版本的 ClosedPort（例如还是 `0.1.0`）
2. 启动后右下角应提示：`发现新版本 0.1.1，可在设置中更新`
3. 打开 **设置 → 关于与更新**
4. 点 **检查更新**，应显示「发现新版本 0.1.1」和更新日志
5. 点 **立即更新**
6. 程序开始下载，然后退出
7. 安装包以 `/S` 静默安装
8. 再打开 ClosedPort，**设置 → 关于与更新** 里当前版本应为 `0.1.1`

到这里，这一轮更新才算完成。

## 6. 用户侧实际会发生什么

### 6.1 启动检查

每次启动，程序请求：

```text
GET http://111.230.247.111/closedport/latest.json
```

- 请求失败：静默忽略，不弹窗
- 没有新版本：不提示
- 有新版本：右下角通知

### 6.2 手动检查 / 安装

路径：**设置（齿轮）→ 关于与更新**

| 按钮 | 作用 |
|---|---|
| 检查更新 | 再拉一次 `latest.json`，对比本地版本 |
| 立即更新 | 仅当检查结果是「有新版本」时可用 |

点「立即更新」后的顺序：

1. 再拉一次清单，确认仍有新版本
2. 按 `url` 下载安装包到系统临时目录
3. 若清单有 `sha256`，校验文件；不一致则中止，不安装
4. `.exe` 使用参数 `/S` 静默安装；若是 `.msi` 则使用 `msiexec /i ... /qn /norestart`
5. 当前 ClosedPort 进程退出，避免文件被占用

## 7. latest.json 每个字段的含义

服务器文件：`/usr/share/nginx/html/closedport/latest.json`

```json
{
  "version": "0.1.1",
  "notes": "给用户看的更新说明",
  "url": "http://111.230.247.111/closedport/ClosedPort_0.1.1_x64-setup.exe",
  "sha256": "安装包的sha256小写十六进制",
  "silentArgs": "/S"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | 是 | 新版本号，必须高于用户当前版本 |
| `notes` | 否 | 设置页展示的说明 |
| `url` | 是 | 安装包完整 HTTP 地址 |
| `sha256` | 建议填 | 空字符串表示不校验；填了就必须和文件一致 |
| `silentArgs` | 否 | 默认 `/S`（NSIS 静默）。不要随便改 |

发布脚本会自动写这些字段。不要只手改 `version` 却忘了换 `url` / `sha256`。

## 9. 常见失败对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动没有任何更新提示 | 清单 version 没有高于本地 version | 先改两个版本号文件，再重新打包发布 |
| 检查更新报「无法连接更新服务器」 | 本机访问不到 `111.230.247.111:80` | 浏览器先打开清单地址确认 |
| 清单打开是网页，不是 JSON | Nginx `/closedport/` 没生效 | 看 `/etc/nginx/conf.d/cng.conf` 是否还有 `location /closedport/` |
| 立即更新报「安装包校验失败」 | 服务器 exe 和清单 sha256 对不上 | 重新跑发布脚本，不要只传 exe |
| 立即更新报「安装包内容为空」 | `url` 下到的不是 exe | 浏览器直接打开 `url` 检查 |
| 点了立即更新，程序退出但没装上 | 安装包不是 NSIS，或被杀毒拦截 | 确认打出来的是 `*-setup.exe`，必要时放行后再装 |
| 发布脚本提示找不到 UPDATE_PASS | 没有 `.update-server.env` | 按第 4.2 节补文件 |
| 发布脚本提示需要 paramiko | Python 没装这个库 | `pip install paramiko` |

## 10. 安全要求

1. 客户端只允许访问 `http://111.230.247.111/closedport/`。
2. SSH 账号和密码只允许出现在本机 `scripts/.update-server.env`。
3. 不要把密码写进 `updater.rs`、前端代码、安装包或 git。
4. 不要把 root 密码发给普通用户。
